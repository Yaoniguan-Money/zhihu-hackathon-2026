# 使用显式配置的 OpenAI-compatible 模型网关

所有模型任务通过 OpenAI-compatible Adapter 接入，并分别显式配置供应商名称、Base URL、API Key 与任务模型；项目不绑定单一厂商、不读取其他工具已有密钥、不提供默认模型，也不自动切换供应商。这样保留供应商可替换性，同时保证缺配置和供应商失败会被直接暴露，而不是以不可验证的降级结果继续游戏。

## 补充决议（2026-09-07，用户明确要求：前端可视配置 + 多供应商按任务路由）

在原决议基础上扩展配置面，请求内行为约束不变：

1. **多供应商注册表 + 每任务显式路由**。配置允许登记 N 个 OpenAI-compatible 供应商（name / Base URL / API Key / 启用开关 / 任务模型表），并为五个任务（claim/case/role/validator/reveal）显式路由到某个已启用供应商及其模型。路由是配置驱动的选择，不是失败恢复：供应商失败的 typed failure 语义不变，仍然禁止请求内静默切换、隐藏重试或 JSON 修复。
2. **运行时配置覆盖层**。供应商注册表存于 Convex 表 `ai_provider_config`（单例），由带口令门控的管理接口读写；表为空时回退到原八项 `AI_*` 环境变量。网关在每次模型调用时解析配置，因此管理页保存后**下一次任务调用即生效**，无需 CLI 或重新部署。
3. **管理口令**。读写管理接口需 `AI_ADMIN_SECRET`（Convex env）；未配置或校验失败返回显式失败。管理界面展示的 API Key 一律掩码。
4. **可观测性**。模型请求失败的 detail 携带 `provider=<name>`，管理界面可读，为"是否切换路由"提供依据；切换本身永远是人（管理员）在配置层做出的显式动作。

原决议的其余约束（八项 env 必填语义作为回退路径、不读取其他工具密钥、无默认模型、`maxRetries: 0`、结构化输出严格复验）全部保持。
